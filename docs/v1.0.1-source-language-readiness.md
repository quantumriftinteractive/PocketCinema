## Confirmed source-language defect and correction

Read-only v1.0.0 device inspection found 11 playable streams for Night of the
Living Dead (1968): one Open Media stream tagged `und`, with English tags on
other sources. The global language menu offered English after Open Media had
been selected. Reapplying source plus language yielded zero matches, before
stream details, subtitle preparation, `/api/play`, or FFplay. The empty-results
path displayed the unrelated first source failure and returned to Home.

The maintenance UI now derives manual language choices from playable streams
matching the selected source, excluding previously failed streams. Blank and
case-insensitive `und` tags are not advertised as verified languages. If no
verified tags exist, the default remains all languages and the message explains
that choice. `All audio languages` remains the first choice when the language
menu is shown; it retains undefined-language streams. `All sources` retains the
union of eligible languages. Saved preferences and final stream filtering remain
on their existing paths. No metadata is guessed or rewritten.

`08fcb7a` corrected empty-results messaging but did not prevent incompatible
source/language choices. This follow-up fixes that cause without changing
playback launch or source eligibility.

## v1.0.0 readiness lifecycle

`start_loading` launches persistent infoPanel. `play_selected_stream` keeps it
visible during subtitle discovery, session creation and subtitle-only Matroska
handoff. `play_url` redirects both FFplay output streams into its temporary log,
starts its resource monitor, and polls for the literal substring
`SDL_SetVideoMode` while the player lives. The first match dismisses the panel,
starts readiness-based watched time and pause tracking. If it never matches,
the panel remains until the player exits. Cleanup then stops the panel anyway.
The same substring participates in the final playback-validity check.

Two executed shell characterization tests simulate a player with/without that
marker. With it, the panel stops while the player lives. Without it, the panel
stops only after exit, and an otherwise zero process exit becomes invalid
playback. These tests demonstrate shell control flow, not physical audio/video.

The signal is a diagnostic dependency, not an explicit first-frame protocol:

- Preserved FFmpeg 2.4.14 `ffplay.c:1116` calls `SDL_SetVideoMode` and logs only
  a fatal error if no surface is returned. A successful call does not itself
  print the readiness substring. The final patch does not add that success
  message; it adds a surface clear and a separate `DISPLAY ...` stderr diagnostic.
- The local vendor SDL binary contains the diagnostic format
  `SDL_SetVideoMode publicsurface ...`; SHA-256 from a read-only device read:
  `0f1ddcb8389c858feee20bca2fdc45551368ce3a57d09eeeaaa2574acdea908b`.
  The local v1 packaged SDK SDL library lacks that diagnostic format (although
  it exports the function name). The normal launcher deliberately preloads
  vendor SDL ahead of the bundled libraries. Actual loaded-library identity on
  the reporter's device remains unknown.
- Audio and video initialize on different paths. FFmpeg starts audio with
  `SDL_PauseAudio(0)` in its audio component path; audible audio does not prove
  that video decoding, filtering or presentation succeeded.
- A different/quieter SDL runtime can initialize a surface without this vendor
  diagnostic. Delayed stdout flushing is another hypothesis if the diagnostic
  uses buffered stdout; its actual output channel/flush behavior on the
  reporter's runtime has not been established. Neither possibility is a proven
  explanation of her incident.
- The panel is a live display process until dismissed, so overlapping display
  ownership is possible. A panel that remains visible is not proof that it is
  hiding otherwise correctly rendered frames. Video startup/filter failure can
  also leave audio running and prevent readiness.
- Complete FFplay output is appended to the UI log only during cleanup. The
  position of a marker in that final combined log does not establish when it
  became visible in the live temporary log.

No readiness or loading behavior is changed in this candidate. A timer-only
panel dismissal or treating audio/process liveness as video readiness would
weaken the accepted progress and startup invariants and is not justified here.

## Subtitle/media paths and physical baseline comparison

A DIRECT source label describes source preflight, not necessarily the final
session. Selecting Matroska subtitles can still trigger bounded video/audio
conversion. The server encodes H.264 Main/yuv420p and AAC into Matroska for the
selectable path; a separate subtitle-only Matroska package is remuxed and handed
to the player for libass filtering/track switching. A nonempty handoff file
establishes preparation, not successful filter initialization or video rendering.
